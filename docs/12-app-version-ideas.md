# 12. 앱 버전 아이디어 메모 (보관용)

- 작성일: 2026-10-15 · 상태: **아이디어 보관 — 앱 버전 설계 착수 시 참조** (현 v2.0 범위 아님)

---

## 1. 문제

- 모바일 앱에서 Twitch 등 중계를 PiP로 띄우면 영상이 상단을 차지 → 캐릭터가 아래로 밀려 하단 인터페이스와 빽빽해지고, 상단 알림은 가려짐

## 2. 전제 — 영상은 앱에 넣지 않는다

- 공식 임베드 플레이어도 제약이 큼: 플레이어 위 UI 겹침·변형 금지, 광고·크기 제약, Twitch 임베드는 웹 도메인 기준, 권리자가 임베드를 끌 수 있음, 치지직·SOOP은 공개 임베드 수단 부족
- Boost 등 수익 기능을 중계 영상 옆에 붙이면 Riot 방송 정책상 별도 허락 소지
- → **앱은 영상을 품지 않는 구조**가 현실적 (약관 해석은 출시 전 법무 확인)

## 3. 아이디어

| # | 방식 | 요지 |
|---|---|---|
| 1 | **세컨드 스크린 (권장 기본 모델)** | TV·PC로 중계, 휴대폰 앱은 Seoha·퀴즈·Boost 전용. 영상 권리 문제 없음, 화면 전체를 캐릭터·인터페이스에 사용 — 익스텐션 시안 구조 거의 그대로 이식 |
| 2 | 같은 기기 시청 시 OS 기능 활용 | Android 화면 분할(공식 앱 위, RORR 아래) / iPhone은 공식 앱 PiP. 설정에서 "영상 위/아래" 선택 → 반대쪽에 중요 UI 배치. 알림은 상단 배너 대신 말풍선·진동·하단 시트 |
| 3 | 경기 중 캐릭터 축소 | 영상이 있을 때 캐릭터는 영상 바로 아래 100~120px 띠(상반신 + 말풍선 1줄), 전신은 평시·경기 후에만 (익스텐션 03-B 원칙과 동일) |
| 4 | 라이브 액티비티 / 진행 중 알림 | iOS 잠금화면·다이내믹 아일랜드, Android 진행 중 알림에 스코어·퀴즈 마감·큰 순간 예고 |
| 5 | 하단 밀도 관리 | 경기 중 입력창 접기, 퀴즈 답·Boost만 크게, 반응 칩은 탭 시 펼침, 높이 단계가 있는 바텀 시트 |
| 6 | 영상 없는 경기 보기 (보완) | Riot 데이터 기반 자체 타임라인·승률 그래프·오브젝트 현황 — 파생 데이터 배포 권리 범위 내 |
| 7 | 가로·태블릿 | 영상 왼쪽 + 패널 오른쪽 = 익스텐션 레이아웃 재사용 |

## 4. 원칙 승계

- "중계 화면은 건드리지 않는다" 원칙은 앱에서도 동일 적용
